# 今日のC++課題：デッドロックしない口座間送金

## 概要

2つの銀行口座間で、複数のスレッドから同時に送金を行うプログラムを作成してください。

送金元と送金先の口座を同時に操作する必要があるため、2つのミューテックスを安全にロックしなければなりません。

## 使用する機能

- `std::thread`
- `std::mutex`
- `std::scoped_lock`
- クラス
- 参照渡し

## 要件

`BankAccount` クラスを作成してください。

### メンバ変数

- 口座名を保持する `std::string name_`
- 残高を保持する `int balance_`
- 口座を保護する `std::mutex mutex_`

### メンバ関数

以下の関数を用意してください。

- コンストラクタ
- 口座名を取得する `name()`
- 残高を取得する `balance()`

### transfer関数

次の形式の関数を作成してください。

    bool transfer(BankAccount& from, BankAccount& to, int amount);

この関数は、次の処理を行います。

1. 送金元と送金先のミューテックスを `std::scoped_lock` で同時にロックする
2. 送金元の残高が不足している場合は `false` を返す
3. 送金元の残高から金額を減らす
4. 送金先の残高に金額を加える
5. 送金に成功した場合は `true` を返す

`transfer` から各口座の非公開メンバへアクセスできるようにする方法も考えてください。

## main関数

次の2口座を作成してください。

- Alice：10000円
- Bob：10000円

2つのスレッドを起動します。

- スレッド1：AliceからBobへ1円を5000回送金
- スレッド2：BobからAliceへ1円を5000回送金

両方のスレッドが終了したら、各口座の残高と残高の合計を表示してください。

## 期待される出力例

    Alice: 10000
    Bob: 10000
    Total: 20000

スレッドの実行順序にかかわらず、残高の合計が必ず20000円になることを確認してください。

## 制約

- C++17を使用する
- グローバル変数は使用しない
- `lock()` と `unlock()` を直接呼び出さない
- 送金処理では `std::scoped_lock` を使用する

## コンパイル例

    g++ -std=c++17 -Wall -Wextra -pedantic -pthread main.cpp -o main
